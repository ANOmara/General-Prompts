About real database connections

Use the Connect button in the toolbar: it opens a connection form for your database and the URL of a small bridge endpoint running on your own local server (browsers cannot speak database protocols directly, so the bridge does that job). The bridge can return the live schema, which is imported here and executed simulated in this page as always. Until your bridge is deployed, export the schema with your tool of choice (mysqldump --no-data, pg_dump --schema-only, .schema in SQLite) and import the SQL file here — multi-schema files are fully supported.

Profile a live connection for your local-server deployment
ⓘ
How this works. A browser page cannot open database sockets itself, so this form talks to a tiny bridge endpoint that you host next to the app on your local server (same machine is fine). The bridge executes the requested action against your database and returns JSON. Credentials are kept in localStorage on this machine only and are never embedded in this file. Imported metadata is then queried by the built-in in-memory engine — always simulated, never sent anywhere.

Bridge API contract (for your local server)

Your bridge receives a POST with a JSON body:
Response for test: {"ok":true,"server":"…","database":"…","version":"…"} — or {"ok":false,"error":"…"}.
Response for schema: either {"ok":true,"ddl":"CREATE TABLE …; -- full DDL dump"} (recommended — supports multi-schema files) or {"ok":true,"schema":{ "table":{ "name","columns":[…],"primaryKeys":[…],"foreignKeys":[…],"indexes":[…],"uniqueConstraints":[…] }, … },"data":{…},"tableSchemas":{ "table":"schemaName", … }}.
Minimal Node example: app.post('/db-bridge', …) → run `mysqldump --no-data` → res.json({ok:true, ddl:dump}). Until the bridge exists, keep importing .sql dumps on the Data dialog.
